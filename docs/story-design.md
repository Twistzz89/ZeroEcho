# 零点回声剧情与规则

实现源为 `entry/src/main/ets/data/StoryRepository.ets`，contentVersion为1。故事学校、人物、设备与记录均为虚构。配置使用显式ArkTS接口，无动态代码执行。

## 内容范围

三章13个普通、谜题或总结节点，加4个结局节点，共17个节点。任务书建议20—24个节点，本版按完整流程收敛为17个，避免增加重复阅读。六条线索、两个谜题和四个结局全部已编码；实际设备试玩时长待记录。

|章节|节点|主要动作|
|---|---|---|
|零点来信|N01—N04|共享/保留/质疑、实验笔记、档案柜|
|错位时间|N05—N12|协作或独查、校准/事件/配置调查、时间线谜题|
|最后报告|N13|提交、主动结束或继续补查|
|结局|E01—E04|完整真相、局部修复、调查中断、未解疑云|

## 两处实际分支

N01共享信息使信任50→60，保留为50，无证据质疑为40。N05的协作入口要求信任至少60，分别到达N06现场口述或N07独立核查。协作口述记录一次性标记witnessed，重复访问后可免费返回，不重复收费。

N08的配置备份入口满足“信任至少60，或已取得CL04”才开放。高信任可直接查配置；低信任必须先查网关日志定位配置位置。两条路线最终汇合，但信任差异仍参与E01判定。

## 线索与谜题

|线索|来源|用途|
|---|---|---|
|CL01实验笔记|take-note，成本1|04-17提示档案编号|
|CL02访问记录|P01成功，成本1|标准时间00:02人员进入|
|CL03校准记录|take-calibration，成本1|网关比标准时间快5分钟|
|CL04网关记录|take-gateway，成本1|本地时间00:05启动回滚任务|
|CL05任务配置|take-config，成本1|标准时间00:00的误设任务|
|CL06校正时间线|P02成功，成本1|任务在人员进入前发生|

P01以字符串校验四位数字，答案0417；空白、字母、417无效不收费，1111格式有效但错误扣1。P02提交HH:mm与业务顺序ID，答案00:00及task-first；合法但错误的时间或person-first扣1。两个谜题首次成功奖励一次，重复提交拒绝。查看提示不扣机会。

## 状态规则与恢复约束

初始18机会、50信任。非负成本由配置声明，信任变化限制0—100。每个成功动作形成独立状态、revision与历史；无效动作返回旧状态。已完成一次性动作与过期revision拒绝。零成本剧情移动仍记录路径，但普通UI返回不触发业务动作。

每次有效动作后首先检查机会是否为0，立即E03；否则仅在N13选择submit/stop时判结局。E01需要CL02/CL05/CL06、P01/P02和信任至少60；E02需要CL02/CL05及P01且未满足E01；主动stop或不足证据为E04。最后提交成本0，剩余1次可提交。结局后dispatch拒绝继续操作。

StateValidator会逐字段检查JSON运行时类型、范围、唯一ID和引用，并按历史重新推导动作成本、信任、奖励、标记、谜题尝试和结局，再与存档比较。类型断言不作为合法性证明。读档不调用奖励入口。
