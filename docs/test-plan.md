# 模块测试计划

测试入口：entry/src/test/List.test.ets，实际套件：entry/src/test/ZeroEcho.test.ets。使用项目依赖的 @ohos/hypium 1.0.21，经 DevEco API17 本地测试能力执行。正常、边界、异常用例均调用生产模块，不替换被测规则算法。

## 被测接口与隔离边界

GameEngine.dispatch/getAvailableChoices、ConditionEvaluator.evaluateConditions、EndingResolver.resolveEnding、StoryRepository.validateStory、StateValidator.validateState、SaveRepository、GameViewModel 为真实实现。FakeTextStore只替换持久化I/O，提供读取阻塞、写入阻塞及指定键写入失败；FixedClock提供固定时间，以便准确比较完整序列化状态。该模拟不证明FileTextStore真实磁盘行为，也不替代设备进程终止与重新启动验证。

## 用例与预期

|编号|类别|输入或前置状态|预期与重点接口|
|---|---|---|---|
|T01|正常|新游戏|起点N01、18机会、50信任、空进度|
|T02|正常|共享信息|原状态不变，新状态17机会、60信任、唯一历史|
|T03|正常|取得CL01后提交0417|P01完成、CL02取得、扣1并保存完整状态|
|T04|正常|CL03/CL04齐全，正确时间和顺序|只比较业务答案，错顺序不完成，正确取得CL06|
|T05—T06|正常|完整/局部证据合法路线|分别E01/E02，解释来自真实状态|
|T07|设备验收|中段存档后彻底结束进程并重启|全业务字段及历史一致；由独立设备验收记录，套件不冒称通过|
|T08|正常|完成结局后新游戏|重置本局，图鉴保留|
|T09—T12|边界|信任59/60、上限100下限0、仅1机会|结局阈值准确，普通行动耗尽E03优先，免费提交正常|
|T13—T14|边界|重复线索/谜题、旧revision、并发双击|不重复扣费、奖励、历史或提交|
|T15|边界|槽位已有数据，取消/确认覆盖|取消不变，确认仅覆盖目标槽|
|T16—T17|异常|空白/非数字/位数不符，以及合法错答1111|无效格式不扣；合法错答扣1并记尝试|
|T18|异常|不存在节点/动作、低信任条件|拒绝且原状态不变|
|T19—T20|异常|坏JSON、缺字段、错误类型/范围、版本不兼容|区分损坏与版本错误，保留原数据|
|T21|异常|自动档主文件写入失败|状态不提交、不显示保存成功，可重试|
|T22|异常|启动读取仍阻塞时点击|不覆盖原存档|
|T23|正常|四条从真实初态出发的操作路径|E01—E04全部可达，无预置结局状态|
|T24|异常|重复ID、错误目标/效果/成本|剧情配置明确拒绝|
|S25|边界|串行提交两个版本|最终保存新版本，旧版本仅为备份|
|S26—S29|异常/正常|损坏主档、手动读删、图鉴写入中断/损坏|显式备份恢复、删除不复活、其他槽不变、图鉴幂等补记|
|S30—S32|边界/异常|all/any、未知条件、两处分支、时间格式错误|组合正确、未知不放行、分支改变可用动作、格式拒绝|
|S33—S34|异常|读取失败或备份写入失败|明确失败、已有数据保留|
|S35|边界|完整证据主动结束、结束后再操作|E04，结局后只读|
|S36|正常/异常|完整E01状态、篡改历史或凭空添加线索|合法状态可保存并测量体积；矛盾历史拒绝|
|S37|正常/异常|有各槽位及图鉴时清空，再损坏主文件|主副本均不复活已清空进度|
|S38|异常|手动读档时自动写入失败|当前显示和已存进度不变，重试可成功|
|S39—S40|异常|主存档或图鉴文件为空，但存在有效备份|不误认作全新数据；存档显式恢复，图鉴加载有效副本|
|S41—S42|异常|主存档或图鉴读取抛异常，副本可读|普通写入不覆盖；确认恢复/初始化修复可重建主文件|
|S43|异常|图鉴主文件为空且备份损坏|初始化失败且零写入，不默认空图鉴|
|S44|边界/异常|已确认新游戏或覆盖不可读槽位|允许替换；未确认覆盖仍保留旧数据|

## 执行方式与证据

在项目根目录运行 scripts/build.ps1 -Task test，或按 README 的 Hvigor test 命令。将 stdout/stderr 保存到 docs/evidence，复制真实 Hypium test_result.txt，并在 test-results.md记载实际数量、失败修复和测试边界。T09—T12直接构造边界状态只验证判定器/引擎；合法路径可达性另由T23证明。

所有列为预期的内容均为测试设计，实际结果以 test-results.md 和原始日志为准。UI确认弹窗、真实文件写入/故障、设备页面可达性及进程重启需要另外验收。
